# GEO 产品级重构候选方案

用户结果：选定一家企业后，能从模型原话追到证据，完成一次内容行动，并用发布后的新轮次比较变化。推荐复用现有监测、Intelligence、知识适配、内容与计划模块，收敛主线；不新建Authority、第二数据仓或合同版本。

依据：[真实接线审计](../audits/2026-10-12-geo-real-wiring/报告.md)、[功能/API清单](../audits/2026-10-12-geo-demo-ui/功能接口清单.json)、[演示浏览器证据](../audits/2026-10-12-geo-demo-ui/报告.md)。按Foundation设计方法§3.1A十步组织。**候选而非已批施工方案**：§3.1A要求完整§10A走查输入；当前缺独立首次目标度量，需补齐后定稿，不以源码认知假扮首次用户。主环境C1–C7仍优先，本方案不授权提前实施大重构。

## 1. 核心闭环

企业运营负责人：选主体/确认准备度 → 运行监测并看原话（G1）→ 核对证据与差距（G2）→ 建计划、生成/保存、人工发布并登记（G3）→ 跑新轮次并比较（G4）。总览只回答现在到哪、最优先下一步是什么。

## 2. 功能归类与新旧映射

| 类别 | 旧入口 | 新位置及理由 |
|---|---|---|
| 主线 | overview | 总览：准备度、当前轮次、唯一下一步 |
| 主线 | monitor、monitor-report | 监测：对象/运行与回答合页，原话始终可追 |
| 主线 | monitor-analysis、insight-overview | 差距：基础观察和解析结论分层，按证据下钻 |
| 主线 | plans、content、assets | 内容行动：计划→稿件→资产/人工发布登记连续操作 |
| 主线 | profile-overview | 企业资料：正式知识可用性与出处，不把GEO资产当企业真相 |
| 辅助 | questions、gaps、action-plan | 分别嵌入监测问题、差距待办、内容行动排序，减少跳页 |
| 辅助 | kb-init、auto-config | 准备度中的设置流程，完成后回主线 |
| 辅助 | report | 总览/差距的导出，注明报告时间与范围 |
| 进阶 | market、battle、faq | 更多中的市场线索、模型对照、FAQ，不占主线导航 |
| 合并 | cognition、cognition-map | cognition有效评估嵌入差距详情，map的问题分布嵌入监测；没有有效评估不出理解分 |
| 删除候选 | 10个GeoDemoFlowPreview替代入口 | 最后一期退役替代页；演示保留同一真实组件的显式夹具，避免无法验表单 |

覆盖全部20目的地；“删除”仅提案，不删除现有数据或业务能力。

## 3. 全局状态

顶部唯一准备度面板：登录有效；主体未选/活跃/停用；采集未运行/运行/部分成功/失败/完成；身份待核/确认；解析待处理/运行/部分失败/完成；知识未绑定/拒绝/不可用/可用但无适用Fact/可用；评估未运行/过期/完成；行动草稿/保存/发布已登记；比较无新轮次/可比较。每项读既有session、items、history、intelligence stats/progress、正式读门与计划字段；无法判定显示未知。观察不依赖知识就能读；正式稿件依赖合法reader与适用Fact；比较依赖发布基线和发布后同范围轮次。各页只保留当前阻断与一个按钮。

## 4. 信息架构

一级：总览、监测、差距、内容行动、企业资料、更多（6项），最多两层。同一主体和时间/轮次选择在顶部共享；账户级资产/资料明确显示账户范围，不随选主体暗示过滤。没有证据证明其归属时不猜测。详细因子、核验、语气、引用留在页面内展开。

## 5. 页面规格卡

| 页 | 目的/唯一主操作 | 条件与空态 | 来源/完成后 |
|---|---|---|---|
| 总览 | 定位当前进度/继续下一步 | 登录；未选主体→选择企业 | items、monitor/overview、stats、distill、知识状态；进入当前必经页 |
| 监测 | 获取可追溯原话/运行一轮 | 活跃主体；未配置→完成监测设置 | items/tasks/run、answers、history、trend；去差距 |
| 差距 | 找最值得处理的有证据问题/创建内容计划 | 有原话；解析未完成→处理待解析回答 | monitor六分析、intelligence聚合/evidence、评估；去内容行动 |
| 内容行动 | 交付一篇可重开的稿件/按当前阶段继续 | 计划；正式来源不可读→查看企业资料状态 | plans、content generate/save/improve、materials、publish/recheck；已登记后回监测跑新轮次 |
| 企业资料 | 查正式事实与出处/查看或补充企业资料 | 合法知识reader；拒绝→申请已有权限流程 | 冻结objects/dossier v2、relations/v5、Evidence v2、chunk v2，经现有统一入口；回原阻断页 |
| 更多 | 低频工具/打开所选工具 | 各工具独立条件，一句缺项+入口 | 现有market/battle/faq/export；完成回来源页 |

“继续”按明确阶段渲染唯一动作，不在同页同时强调生成、发布和复测。首次稿件保存后能重开并追到生成时Fact/Evidence；当前资格仍实时核验。

## 6. 数字口径

| 名称 | 算法与范围 | 唯一来源/位置 |
|---|---|---|
| 问题提及覆盖 | 最近所选主体轮次，有确认提及的问题/有有效回答的问题 | monitor/overview；总览和监测引用同值 |
| 回答提及率 | 所选主体/明示时间窗，确认提及回答/成功回答，未知单列 | 现有monitor分析源；差距；不叫推荐率 |
| 语气分布 | 主体确认且被提及回答中正/负/中立计数；失败、未知单列 | monitor/sentiment；监测/差距 |
| 推荐份额 | 解析期我方推荐计数/全部品牌推荐计数 | intelligence/sov；差距；不是推荐概率 |
| 理解有据占比 | 同主体同轮次评估grounded claim/全部claim | 修复后的cognition/profile；差距详情；修复前不展示主体分数 |
| 内容效果变化 | 发布基线与发布后同主体、同问题、同模型范围的新轮次指标差，单位百分点 | 修复后的content-recheck；内容行动；缺新轮次为不可比较 |
| 资产数/运行次数 | 账户资产数/历史运行记录数 | stats/overview；总览次级统计，标账户范围 |

后台统一失败分母、主体/时间窗与ID，前端不自己修数字。历史不可归属记录保留标记，不能自动回填。rank_est仅是句序，降为原话详情字段；“差异化/竞品防御力”不能直接套推荐倾向/理解占比，需要证据后再恢复。

## 7. 词表

统一“总览”（替数据中心/经营总览）、“模型回答”（原话）、“差距”（认知洞察/差距诊断入口）、“理解评估”（品牌理解/认知健康详情）、“内容计划”（行动计划）、“内容资产”（GEO稿件/素材）、“企业资料”（Foundation正式知识）、“发布登记”（旧发布按钮）、“新轮次对比”（旧复测按钮）。资料缺少依据与竞品领先分成不同结论，缺少依据不能叫事实错误。

## 8. 文案

正文保留结论、样本范围和动作；边界长文收详情。空状态写具体缺项并给一个动作；失败、拒绝、未解析、无样本不得共用“暂无数据”。局部读面失败可显示其他结果，但必须在对应读面暴露失败和重试。演示在全局显著标记，退出时清除夹具状态。

## 9. 分期与施工范围

前置接线修复独立开卡：Product API progress门（共享唯一写者）；认知评估绑定稳定回答/主体/批次（GEO）；效果统计限定主体、成功回答及发布后轮次（GEO）；正式reader/dossier接缝（A线）。先证首偏离，沿原链WRITE→READ BACK→VERIFY。身份、数据迁移与口径变更分别裁定，不由界面方案暗中放宽。

一期：全局状态+导航+文案，范围main.tsx、geo-advisor/index.tsx、shared.tsx、geo-monitor-subject.tsx、GeoEnterpriseOverview.tsx、页面壳及index.css；复用已有读面，仅展示可证明状态，progress待责任人交付。🟡界面结构卡待批。二期：monitor/report/analytics/insight/cognition/profile/plans/content/assets组件合并、后台口径接线；数据/合同变化另卡🟡/🔴。三期：确认旧入口无消费者后删除重复入口与演示替代页，保留数据与历史证据。每期独立构建回滚制品；在用dist禁止覆盖，未证明兼容的数据迁移不执行。

## 10. 验收与第一期卡

用G1–G4从登录首页复走：每目标达成，死胡同/环路/矛盾=0；点击数低于独立基线，首次迷路步数后移或不发生。同一个稳定回答能追到解析/评估/计划；两个企业不会共享评估；失败模型不计成功分母；无新轮次不能出效果；权限撤销不借快照，重开保留ID和出处。真实Provider/正式知识验证须由主环境负责人按既有预算执行，隔离替身不替代。

第一期卡草案 GEO-R1：目标=用户明确当前主体、哪些阶段未完成及唯一下一步；范围=一期文件；先决=补完独立§10A目标度量、中控登记唯一写者及与主轴并行许可；验证=临时输出npm run check:ui、同目标浏览器复走、部分读面错误与切主体测试；回滚=上一独立UI制品；不改后端/门/身份/资料/部署，不提交现有混合dirty。卡未批准，当前交付为方案及审计，不实施。
