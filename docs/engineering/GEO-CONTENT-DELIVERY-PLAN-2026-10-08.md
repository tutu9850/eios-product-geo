## 1. 业务目标与范围

首版用户是经 EIOS Client 登录、拥有 GEO 使用权限的企业内容负责人。输入是一份允许使用的真实企业资料、明确企业/产品身份及写作主题；预期生成企业介绍和产品 FAQ，按指令改写，保存后重新打开，能查到每个具体企业主张的资料依据。最终交付可由人审核和发布的草稿，不把模型输出变成企业正式 Fact。

**MISSION：用现有内容系统完成一条可追溯、账号隔离、错误真实的草稿交付链。**

IN：GEO 内容生成/改写/保存/读取、相关资料筛选与来源投影、必要的身份隔离及错误传播；Product API 耗时接缝列为跨仓依赖；Knowledge 手动同步和正式 Fact 按后续阶段分别验收。

OUT：自动发布、自动画像/缺口/选题全套、监测和情报重构、Provider 自有接线、Foundation 治理 Phase 1/2/3 施工、自动 successor/迁移、旧关系全量退役、历史数据清理、数据库体系迁移、新 Authority/Registry/Ledger/任务队列。

本轮是文档任务，IN 是后续拟议范围，不表示这些代码已获本轮执行授权。

## 3. 当前实际链与复用点

```text
Client / Product Host
  → Product API /api/product/geo/*（认证、scope、代理）
  → GEO product door → /api/v1/content/*
  → services/content（选材、prompt、生成/改写）
  → adapters/llm → Model Capability → 受治理 Provider
  → GEO 内容资产保存 → 正式产品读门 → UI 重新打开

资料输入：
当前账号 GEO 上传素材 → 现有 kb / chunks
手动 Knowledge 同步 → 正式 Knowledge 读门 → 非权威 GEO 快照
运行时选材默认读快照，不自动实时访问 Knowledge
```

## 4. 首版最小实现方向

### 4.1 本篇选材与来源

用户明确公司/产品身份并选定允许使用的企业资料；不要求先存在 Semantic 分类或 Knowledge 实体。用户填写名称是写作输入，不是 canonical identity，也不能授予跨柜访问。

先复用现有素材、切块、相关性排序和存储扩展点。按当前柜解析素材 ID，检查选择范围；前端传来的来源标签、ID 或正文不能自行变成正式依据。主题检索应排除零相关项，缺失时报告待补资料，不拿“最新资料”补位。

明确分层：正式 Fact、Knowledge 原文/非正式材料、GEO 上传资料、历史生成内容、问题池/市场观察。历史生成稿默认不能作为具体企业主张的独立支持；用户资料可以支持“据企业资料”的草稿表述，不能冒充 Authority 已验证。

本篇需贯穿生成、改写、保存和读取的来源信息：本地素材/切块 ID、实际使用选段及摘要校验值；Foundation 提供的 Document/version/chunk/Evidence 引用；来源类型、读取/同步时刻、非权威或过期标识。缺失的正式版本/Evidence 不补造。历史稿若无来源，显示未记录，不能追补成当时已引用。

优先在现有产品记录中保留来源元数据，不预定新表、Registry、Ledger 或正式版本机制。施工前证明既有字段/持久化能否承担；如必须新增 schema 或改变正式合同语义，按纪律进入最小裁决，不先实现。

### 4.2 生成与改写一致

生成和改写使用同篇已解析的材料集合，不在改写时悄悄重新捞一套资料。用户选择新增资料时明确记录本次依据变化。企业名称未自动识别不应掩盖“用户已明确身份、已有上传资料”的合法写作场景，但实现前核对现有身份规则。

核验从实际正文开始，至少覆盖金额、数量、客户、案例、资质和承诺等具体企业主张。确定性数量/引用匹配优先复用；语义判断不能仅靠字符串出现，也不能把另一个模型意见当正式事实。结果区分“本篇资料有支持”“待人工核验”“资料不支持”；无依据主张删除或标注待核验。

strict 的用户说明与真实核验范围一致；未覆盖主张不能显示全文已核验。生成后和改写后均检查。GEO 保存的核验结果只是产品诊断，不产生 Foundation Fact 或 Evidence。

### 4.3 同步、失效和错误

Knowledge 同步区分未同步、成功无数据、无命中、无权限、不可达、坏响应、部分失败和旧快照；资源隐藏型 not-found 仍尊重 Authority 既有权限策略，不能为了 UI 区分泄露不可见资源。

不能简单清空历史台账，也不能继续把已失效对象认作当前 active Fact。先调查正式快照/版本/撤权规则和既有机制。未解决撤权与有效期前，不开放个人/部门快照自动消费；未能证明事实当前有效时，只作历史来源展示或停止该事实注入。

### 4.4 时间预算

核对 UI、Product API、GEO、Model Capability、Provider 的实际超时、取消和重试预算。在 Product API 内按现有耗时路由机制处理生成/改写，不把 manage 改成 run 来扩权。首轮保留同步 API，预算不够时明确失败；不为避超时新增队列或无限重试。

## 5. Foundation 最低消费条件

| 阶段 | Foundation / 平台必须具备 | 可以暂缺 | 放行依据 |
|---|---|---|---|
| A：GEO 上传资料草稿 | 正式 Actor/产品会话、允许的产品门；Model catalog 默认模型、binding 与一次真实调用 | Knowledge 样本、完整 Fact、关系、Semantic 分类 | 一份资料生成企业介绍和 FAQ，改写保存读回，账号隔离 |
| B：手动同步原文 | 正式 Knowledge 读门、合同、授权主体；真实文档选段与版本/来源可读；同步错误和失效表达 | 全库治理、完整语义网络 | 使用 GEO 实际获授权身份读到相关原文，版本来源可回查，撤权/变更处理成立 |
| C：正式 Fact | 当前有效 Fact、主体/属性或关系/值、Evidence 与版本；失效不再进入新稿 | 无关领域的治理、全量关系迁移 | 对本场景相关事实做合法读回和生命周期验收 |
| D：自动画像/缺口/选题 | 对应 Definition → Instance/Fact → Evidence 可读可解释，真实业务样本 | 无关语义领域完整度 | 独立后续业务卡，本轮不启动 |

Foundation 文档控制面的 Phase 1 READY 不能替代部署验收。GEO 当前出站 subject 默认是服务主体，与 human:alice 不同；应核验真实 Actor、服务执行身份和资源可见性，而不是让服务冒充用户或自行加 scope。账号柜只控制 GEO 本地隔离，不能替代 Foundation ACL。

正式关系消费按 Foundation 2026-10-07 当前裁决使用正式 Fact/Evidence 读面；旧 instance-relations 是后续迁移依赖，不作为新正式链依据，不在第一阶段顺手删除共享 reader 或数据。

## 7. 验收与失败矩阵

用户指定的真实测试资料为 `/Users/tutu/Desktop/笔革家居GEO/`（2026-10-08 已确认存在）。优先从主理人访谈纪要、现场调研手册与调研 PDF 中核对适合企业介绍/FAQ 的内容；两个 Markdown 导出先查来源性质，历史生成内容不当独立事实依据；合同不默认作为公开宣传素材。保持原件只读，测试保存到任务专用临时库。对用户用大白话说明结果。前端资料入口是“内容资产 · 文件管理 → 上传文件”，不是 Knowledge 同步；当前 DOCX 上传解析仅读取顶层段落，表格内容完整性需列为真实样本测试项，不能以上传成功证明全部文本已提取。

成功路径用真实、允许使用的资料生成一篇企业介绍和一篇产品 FAQ；逐项检查资料中的数字、产品和主体不张冠李戴；改写后来源保持对应；保存后从正式入口重开，再在授权的专用服务重启后读回。人工审核是发布步骤，不替代账号隔离、错误传播或持久化验收。

| 样例 | 必须观察的结果 |
|---|---|
| 空资料/空正文/非法长度等输入 | 合同拒绝或明确资料缺口；无伪成功草稿 |
| 合同错误或缺失字段 | 沿原链明确错误；不接受坏模型响应 |
| body tenant / 他人素材 ID / 跨企业引用 | 不影响已验证身份；拒绝或依法隐藏资源；不泄露内容 |
| 能力缺失或授权拒绝 | 如实显示不可用/拒绝，不退回 GEO 自有模型 |
| Provider 失败 | 保留真实错误，不生成空成功或错误保存 |
| Knowledge / Authority 拒绝 | 尊重正式门语义，不借快照越权继续 |
| 保存失败或冲突 | 不显示已保存；原稿可恢复；不产生残缺引用 |
| 资料修改/版本变化 | 指明本稿使用的原依据；新稿不静默使用旧 active 资格 |
| 重复保存/重复请求 | 按现有接口语义验收，不假定已有幂等；不另建 ledger |
| Timeout / 用户重复提交 | 错误和副作用可核实；有限重试，不显示两个不一致成功 |
| 部分同步/中断/部分模型结果 | 保留完成与失败范围，不标整链成功 |

每类记录输入、期望、实际错误、持久化副作用及 UI 结果；不适用说明理由，未测明确标记。整链报告包含写门确认、合法持久化读回、Product API 消费读回、UI 读回及重启后复核五层证据。GEO 草稿写门是产品资产操作，不是 Foundation 真相治理门。

## 8. 验证、成果和风险

代码施工按本仓要求运行 `python -m pytest` 与 `npm run check:ui`。测试使用 `/tmp/eios-test/<task>/` 下独立临时库、媒体目录及端口；核实所有测试读写路径，不读写开发 `geo.db`。沿用 Foundation 包路径，缺包先分类为环境问题；UI 构建产物放任务临时目录，或使用经核实的可逆构建方式，不提交产物、不覆盖既有文件。Product API 若有改动，按其工作规则运行定向代理/超时/身份回归。

提交可接手的最终报告，说明首断点、同层调查、实际文件/函数、契约/数据影响、真实身份、测试、五层读回、未测项、范围扩展及 DONE/PARTIAL/BLOCKED。中间只留短 checkpoint；当前现场链接报告，不把进度散落回 README。
