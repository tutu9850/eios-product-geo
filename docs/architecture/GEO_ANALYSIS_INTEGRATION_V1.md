# GEO 分析整合方案 V1

状态：**实施中**（2026-09-26）  
适用范围：`eios-product-geo` 的监测分析与客户认知入口。监测对象管理页不在本方案内。

## 1. 要解决的问题

当前六个分析页分别回答品牌舆情、评价、事实、竞品、行业和信源，用户需要自己把六份结果拼成结论。客户认知地图又把“最近一批回答的提及覆盖”和“历史语义评估分数”放在一起，虽然数据源不同，却没有给出足够强的范围提示。

这会带来三种误读：

- 负面占比被读成“客户不喜欢”，但它只是模型回答中的规则情绪信号。
- 提及覆盖被读成“准确认知”，但它只说明有效回答中出现了品牌。
- 历史认知维度和当前批次覆盖被相加或横向比较，样本范围却不同。

## 2. 唯一主线：Visibility Case

分析页只围绕一个可复测的可见度案例组织：

```text
Subject / Monitor
  -> 一批问题 × 国产模型回答
  -> Observation / Answer 状态
  -> Evidence 是否足够
  -> 一个优先差距
  -> 一个下一动作
  -> 复用同一问题集复测
```

页面默认只给出最多三个可执行判断，详细分析降到“核对证据”区域。任何判断都必须同时带出样本范围、回答数和证据状态；没有有效回答、主体不明确或知识库不可用时，显示“未判定/证据不足”，不显示 0 分或确定性企业事实。

## 3. 六类分析如何归并

| 原分析 | 统一回答的问题 | 作为主判断的输入 | 默认输出 |
| --- | --- | --- | --- |
| 品牌舆情 | 哪个客户问题正在产生风险信号？ | 最近一批有效回答、负面占比、风险问题 | 负面集中问题 + 原始回答入口 |
| 评价分析 | 模型用什么语气描述品牌？ | 正/负/中与未判定样本 | 语气信号，不升级为客户事实 |
| 事实核验 | 这些说法有没有企业资料或来源支撑？ | claim_checked、hit_kb、unsupported、knowledge_ok | 证据缺口 / 可核验 / 不可判定 |
| 竞品分析 | 相同问题上相对谁存在差距？ | 同题有效回答和提及率 | 相对差距，不等同于市场份额 |
| 行业提及 | 行业回答中出现了哪些企业？ | 行业对象、有效回答、规则识别提及 | 行业语境线索，不等同于推荐 |
| 信源分析 | 哪些模型的可见度不同？ | 每模型有效回答与提及率 | 模型差异，用来定位复测优先级 |

三组产品判断：

1. **被看见**：舆情风险 + 模型差异 + 决策阶段覆盖。
2. **说得可信**：事实核验 + 原始回答 + 来源/引用。
3. **下一步**：按问题、证据强度和执行成本选择问题池、知识缺口或内容动作。

竞品与行业信号只有能改变问题集或下一动作时才进入前三条判断，否则留在详细分析里。

## 4. 客户认知地图的正确位置

客户认知地图不是第七套评分系统。它只作为“当前批次覆盖”和“历史认知评估”的解释上下文：

- 当前批次：按最近一批品牌探针的**有效回答**计算提及覆盖；`mentioned = null`、失败和未回答不进入分母。
- 历史评估：只显示已有语义评估的维度；没有评估就是“未评估”，不能当作 0。
- 两者必须有清晰的样本范围和时间说明，不合成“客户认知总分”。
- 低覆盖阶段直接连到问题池；证据不足连到资料/知识缺口；有可执行缺口才连到内容计划。

原“客户认知地图”入口现在复用整合后的监测分析上下文，避免用户在两个页面看到两套互相解释不了的数字。

## 5. 统一页面结构

```text
监测分析
  监测主体 / 范围
  当前范围与样本状态
  三条优先判断
    判断 -> 样本/证据依据 -> 下一动作 -> 复测入口
  客户认知地图（解释上下文）
  六类详细分析（折叠，按需核对）
```

详细分析不是删除，而是从默认主叙事中降级。它们仍保留原始回答、趋势、排行和平台维度，用户点击判断后可以核对完整明细。

## 6. 当前实现边界

本轮只改前端呈现与语义：

- `GeoMonitorAnalytics` 并行读取六类现有接口和认知上下文，生成三条有范围的判断。
- `GeoCognitionMap` 复用整合分析入口，不再独立渲染两套分数。
- `GeoMonitorReportCard` 明确标注模型原始回答是 Observation；主体未确认或没有依据的回答不作为企业事实。
- 监测对象管理组件、接口和计数逻辑未修改。

后端仍有已知边界：legacy `/monitor/check` 的 Quick Check 没有可信 `monitor_id` 关联，且当前 `/monitor/answers` 不把无 monitor 的单问检查纳入答案列表。要把 Quick Check 纳入跨次趋势，需要单独的后端合同和迁移卡，不能在前端偷偷混入。
