## 1. 目标

GEO 内容生成的核心任务不是重新理解、重建或表达企业语义。

GEO 的职责是：

从企业当前可用的原始资料中，找到与当前生成任务最相关、信息覆盖最完整、重复最少的原文片段，组成 Context Pack，交给模型生成内容。

- GEO 不建立第二套企业语义体系。
- GEO 不负责把企业知识重新抽象成自己的实体、属性、关系。
- GEO 不以 Semantic Object / Fact 的机器化表达作为文章主要语言来源。

## 2. 核心原则

### 2.1 原始文档是 GEO 文章生成的主要语言来源

企业原始文档具有完整上下文、自然语言表达、业务细节、数据、案例、企业自己的措辞。
因此文章生成优先使用 **Document Chunk**，而不是要求模型从结构化语义对象重新组织企业语言。

### 2.2 Chunk 是内容选材的基本单位

生成选材不能以整篇 Document 作为最小相关单位。必须以 **Chunk** 作为相关性计算和候选选择的基本单位。

一份 Document 可以包含大量无关内容。因此「这份文档相关」不能等价于「这份文档的全部内容都相关」。

### 2.3 GEO 不负责创造企业事实

模型只能基于最终 Context Pack 中提供的企业资料生成内容。如果 Context Pack 没有足够证据：
不得通过模型自行补齐企业事实。缺少资料时，应允许生成 **信息不足 / 未找到相关资料**，而不是编造。

## 3. 数据来源

GEO 内容生成可以消费多个来源，但来源必须区分。

### 3.1 原始企业文档

包括但不限于 DOCX / PDF / XLSX / CSV / TXT / Markdown / OCR 后文本。

进入 GEO 后以 **Document → Chunk** 形式参与选材。这是 GEO 内容生成的主要来源。

> **Owner 裁定 4（2026-09-21）**：Knowledge 侧原始文档与 GEO 侧「用户上传企业素材」
> 是**两个来源**，但**统一按 Raw Material → Chunk 算法处理** —— 同一套分段、同一套相关性、
> 同一套去重与覆盖规则，只在 §15 的来源分层与 §13 的 `source_type` 上区分。

### 3.2 Knowledge 正式事实

Knowledge 中已经存在的正式事实可以作为 **事实约束 / 辅助证据**，但不要求 GEO 把这些事实重新转换成自己的语义体系。

> **Owner 裁定 2（2026-09-21）**：正式事实**降级**为事实约束 / 辅助证据，
> **不再作为文章主要语言来源**，也不排在原始文档切块之前。
> 对应施工口径：事实不得占据 Context Pack 的主要名额，不得压过 Raw Material Chunk。

### 3.3 非企业语言来源（Owner 裁定 3）

FAQ 资产、客户问题池、市场现状信号**保留**，但必须**标记为「结构参考 / 现状参考」**，
明确它们**不是企业语言来源**，不作为企业事实依据。

## 4. 第一阶段：硬过滤

（Owner 原文未展开；施工前必须补齐口径：来源合法性、租户/权限、时效性、类型白名单等。
本阶段只做**排除**，不做相关性判断。）

## 5. 第二阶段：Chunk 召回

生成任务首先形成当前任务的 Query。Query 不等于简单复制用户输入。应提取：
核心主题、核心业务词、产品词、人物词、客户词、行业词、数据指标、时间词、用户明确要求的信息类型。

停用词不得作为主要相关性依据。

> **Owner 裁定 1（2026-09-21）**：Knowledge 侧暂时拿不到全文 Chunk，**先按命中 Chunk 施工，不等 Knowledge**。
> 施工口径：GEO 侧素材（Raw Material）做**全量 Chunk 召回**；
> Knowledge 侧只能对**检索命中的 Chunk** 做 Chunk 级计算 —— 且必须如实标注这一上限，不得宣称全量。

## 6. Chunk 相关性

每一个 Chunk 独立计算相关性。第一版不要求向量模型参与。优先使用现有确定性检索能力：
keyword、n-gram、phrase、实体词命中、数字 / 指标命中、标题 / 小节标题命中。

## 7. 相关性计算原则

Chunk 的相关性至少考虑以下因素：

```
Chunk Relevance
  = 核心词命中 + 词组命中 + 关键词覆盖 + 局部词距
  + 标题/小节命中 + 实体命中 + 数据命中
  - 噪声
```

具体权重不得凭经验直接拍定。必须先使用真实 GEO 数据进行离线评估，再冻结具体参数。

## 8. 禁止整篇累计命中

**这是本算法的关键不变量。**

禁止：

```
Document A:
  Chunk 1  命中“无锡”
  Chunk 8  命中“演示间”
  Chunk 15 命中“成交”
  => 因为整篇三个词都出现过，所以判定高度相关
```

这种计算方式会导致：长文因为到处碰巧出现关键词而获得虚高相关性。

正确方式：Chunk 1 / Chunk 8 / Chunk 15 **各自单独计算**，
然后根据 Chunk 的实际相关程度决定 Document 是否值得进入生成上下文。

## 9. Document 层级排序

Document 不是相关性计算的最小单位，但仍需要进行文档级排序。
Document 的相关性应由其内部 Chunk 的相关性产生。

基本原则：**最高相关 Chunk 是 Document 进入候选排序的主要依据**；同时可以考虑多个高相关 Chunk 对 Document 的增益。

禁止：把整个 Document 所有关键词命中简单累加作为最终分数。

## 10. 最终选材不是简单 Top-K

仅仅取「相关性最高的 K 个 Chunk」仍然存在问题。

例如：Chunk A/B/C/D 都是产品介绍、Chunk E 是客户案例。
如果 A/B/C/D 都非常相似，单纯 Top-K 会造成 Context Pack 被同一种信息占满。

因此最终选择必须同时考虑：**相关性、信息覆盖、重复度**。

## 11. 信息覆盖

选择第二个及之后的 Chunk 时，需要判断：这个 Chunk 是否提供了前面已经选中的 Chunk 没有的信息。

例如：
- Chunk A：公司主营 AI 获客。
- Chunk B：公司主营 AI 获客，并服务家居企业。
- Chunk C：公司已经服务 300 家企业。

A 已经覆盖「AI 获客」，因此 B 的新增价值有限。C 提供「企业数量」，因此应该获得更高的新增信息价值。

## 12. 去重

多个 Chunk 如果表达高度相同的信息，不应该全部进入 Context Pack。
第一版可以使用确定性文本相似度进行去重。

候选 Chunk 之间应计算：n-gram 重叠、词集合重叠、文本相似程度。
高度重复时保留相关性更高者。
如果两个 Chunk 来自同一 Document 的连续段落，且内容具有自然上下文关系，可以作为连续证据保留。

## 13. Context Pack

最终交给模型的不是 Document 列表，而是 **Context Pack**。Context Pack 中每个材料至少包含：

```
source_type
document_id
document_title
chunk_id
chunk_ordinal
chunk_text
relevance_score
selection_reason
```

其中 `chunk_text` 是模型真正使用的主要企业语言来源。

> **Owner 裁定 6（2026-09-21）**：`relevance_score` / `selection_reason` **必须加**。
> 来源定位必须到「文档 + Chunk」。**但不得虚造 Knowledge 侧 ordinal** ——
> Knowledge 拿不到文档全文时，ordinal **如实为 null**，不许猜、不许编号。

## 14. Context Pack 的选择原则

最终 Context Pack 应满足：**高相关 + 高信息覆盖 + 低重复 + 来源合法 + 来源可追溯**。

而不是：尽可能多塞资料。资料越多不一定越好。如果资料与任务无关：不进入 Context Pack。

## 15. 来源优先级

不同来源不能被视为完全相同。建议采用：

```
企业原始文档
    ↓
Knowledge 正式事实 / 约束
    ↓
用户上传企业素材
    ↓
GEO 历史生成内容
```

这里的「优先」指：**作为企业信息依据时的权威程度**。不是说低层来源完全不能使用。

## 16. Context Pack 来源分层（Owner 裁定 8 补齐）

Context Pack 中每一层**只能承担它被允许承担的职能**。分层与 `source_type` 的映射：

| 层 | 来源 | `source_type` | 职能 | 允许作为企业语言来源 | 名额性质 |
|---|---|---|---|---|---|
| L1 | 企业原始文档（Knowledge 侧文档 Chunk） | `knowledge_document_chunk` | 企业语言主来源 | **是** | 主体名额 |
| L2 | Knowledge 正式事实 / 约束 | `enterprise_fact` | 事实约束、辅助证据 | 否（是约束不是措辞） | **封顶**，不得压过 L1 |
| L3 | 用户上传企业素材（GEO 侧 Raw Material Chunk） | `uploaded_material_chunk` | 企业语言主来源 | **是** | 主体名额 |
| L4 | GEO 历史生成内容 | `generated_asset_chunk` | 参考，**不得覆盖 L1/L3** | 否（避免自我循环） | **封顶 + 降权** |
| R1 | FAQ 资产 | `faq_asset` | **结构参考**（已有问答的形态） | 否 | 参考名额 |
| R2 | 客户问题池 | `question_pool` | **结构参考**（文章要覆盖的问题） | 否 | 参考名额 |
| R3 | 市场现状信号 | `market_signal` | **现状参考**（AI 现在怎么答） | 否 | 参考名额 |

分层规则（施工不得违反）：

1. **L1/L3 是 Context Pack 的主体** —— 只有它们提供「企业原文措辞」。
2. **L2 是约束**：事实只用来「不许写错」，不提供文章语言；且**必须封顶**，不得因为数量多而挤掉 L1/L3。
3. **L4 降权**：GEO 自己写过的内容回到生成里，最高只能是参考，不得覆盖企业原文（防蒸馏自我循环，见 §2.3 与不变量 6）。
4. **R1/R2/R3 一律标注为参考**，在 Context Pack 与来源面板中必须可见地区分于 L1–L4。
5. **跨层不合并计分**：不同层不共享同一套相关性分值排名（否则「数量多的层」会系统性挤掉「权威高的层」）。

## 17. 无相关资料

如果候选 Chunk 全部低于最低相关阈值：**不得为了凑数量继续塞入无关资料**。

应返回「没有找到足够相关的企业资料」，或者由上层生成逻辑明确知道：当前信息不足。
**不得静默使用随机资料填充 Context Pack。**

> **Owner 裁定 5（2026-09-21）**：**禁止**拿最新资料凑数，改为**信息不足**。
> 对应施工口径：无命中必须**显式**表达（来源面板与生成结果都要看得见），
> 不许静默退回「按最新取」。这是产品可见的行为变化，已由 Owner 确认。

## 18. Context Pack 数量

第一版不得固定认为：一定要取 N 篇文档。
数量应该受以下因素共同限制：模型上下文预算、当前任务复杂度、Chunk 相关性、信息覆盖度、重复程度。

最终原则：**少而相关 > 多而杂**。具体 Top-K 参数必须通过真实数据评估后冻结。

## 19. 生成阶段

模型收到：**用户生成任务 + Context Pack + 生成规则**。

模型负责：将 Context Pack 中的企业材料重新组织成自然语言内容。
模型不负责：自己搜索企业知识、自己补企业事实、自己创造企业背景、自己把缺失信息想象出来、自己建立第二套企业语义。

## 20. 可追溯性

每一段最终进入模型的企业材料必须能够追溯到：**Document → Chunk → 原始文本**。

用户最终看到的来源，应能够定位到具体 **文档 + Chunk**，而不是只告诉用户「来自某某文档」。

> **Owner 裁定 6（2026-09-21）**：来源面板必须能显示到 Chunk。
> Knowledge 侧拿不到 ordinal 时**如实显示「未提供段号」**，不得编造。

## 21. 评分参数的冻结方式

本文件冻结：**算法结构**。
暂不凭经验冻结：各项权重、相关性阈值、Top-K、去重阈值、覆盖度权重。

这些参数必须先用真实企业资料进行离线评估。评估集至少应包含：
企业介绍、产品介绍、客户资料、案例、数据资料、长文档、多主题文档、
关键词分散在不同 Chunk 的文档、多个高度相似 Chunk、无相关资料的任务。

评估后再形成：**GEO Content Selection Parameters v1**（单独冻结参数版本）。

## 22. 当前阶段明确不做

GEO 自建 Semantic Object / Entity / Relation / Knowledge Store；
GEO 自己抽企业语义；GEO 自己维护事实分类体系；GEO 自己维护「负责人=人物」等关键词分类表；
GEO 向量化；GEO 私自连接模型；
改 Authority；改 PDP；改权限模型；改 Knowledge 上游抽取链路。

## 23. 核心不变量

1. **Chunk 是内容选材的基本相关性单位。**
2. **不得用整篇 Document 的关键词累计命中代替 Chunk 相关性。**
3. **最终选材必须同时考虑相关性、信息覆盖和重复度。**
4. **GEO 使用原始文档 Chunk 作为主要文章语言来源。**
5. **GEO 不建立第二套企业语义。**
6. **没有证据不得生成企业事实。**
7. **每一个进入 Context Pack 的 Chunk 都必须可追溯。**
8. **算法结构先冻结，具体参数必须通过真实数据评估后冻结。**

## 25. 最终目标

```
用户生成任务
      ↓
任务需求
      ↓
候选 Document
      ↓
Document → Chunks
      ↓
Chunk 相关性计算
      ↓
Document 候选排序
      ↓
重复过滤
      ↓
信息覆盖重排
      ↓
Context Pack
      ↓
LLM
      ↓
自然语言内容
      ↓
Chunk 级来源追溯
```

核心思想只有一句：

> 不是让 GEO 再理解企业，而是让 GEO 找到企业原文里最值得读的那几段，
> 然后让模型把这些真实材料写成自然语言。
