# GEO 前端补齐与产品信息架构方案

基于 `GEO_FUNCTION_INVENTORY.md`（2026-09-21）与当前 Client 内嵌版 GEO。

## 1. 产品主线

前端不按 139 条接口组织，也不把每个能力做成菜单。用户只需要理解一个闭环：

**建立企业事实 → 监测国产大模型 → 找到认知差距 → 采取增长行动 → 发布并复测**

一级导航收敛为 6 个用户任务：

1. **总览**：现在表现如何，最该做什么。
2. **监测**：监测谁、何时监测、模型如何回答。
3. **洞察**：为什么被提及、与竞品差在哪里、证据是什么。
4. **行动**：问题、缺口、计划、生产、发布、复测。
5. **资料**：企业事实、素材资产、资料完整度。
6. **市场**：竞品信号、内容收录、行业机会。

“AI 对战、报告、引擎检测”不再占一级导航，分别作为监测页工具、总览页报告入口和设置抽屉出现。

## 2. 给普通用户看的能力

### A. 总览

- 品牌推荐率、平均排名、引用率、SOV、趋势变化。
- 国产模型横向表现与异常提示。
- 企业资料健康、知识缺口、内容计划、链接收录状态。
- “本周最值得做”行动清单。
- 最新周期报告、人话版管理摘要、PDF 导出与重新生成。
- 数据源：`monitor/overview`、`rank-sentiment`、`intelligence/humanize`、`sov`、`trend-delta`、`reports/latest`、`distill/overview`、`stats/overview`。

### B. 监测

采用“对象与任务 / 分析 / 回答明细”三层结构。

- 对象与任务：对象 CRUD、探针预览、任务编排、单次运行、任务运行、趋势详情。
- 分析页签：表现总览、评价与舆情、事实核验、竞品、行业、信源、引用。
- 回答明细：按问题、模型、时间、对象筛选原始回答；支持导出。
- 辅助工具：AI 生成客户问题、AI 对战。
- 用户不需要看到 `/monitor/batch`、`/monitor/check` 两个技术执行入口，统一由“运行监测”按钮调用产品推荐流程。

### C. 洞察

采用“结论 → 差距 → 证据”渐进式结构。

- 汇报层：一句话结论、SOV、品牌/竞品提及率、趋势得失。
- 诊断层：认知八维、认知总表、差距矩阵、因子左右对比、知识缺口与证据缺口分离。
- 证据层：点击任一认知因子，从右侧抽屉查看模型原话、传播强度、来源与关联因子。
- 策略层：关键词、标签分布、GEO Action Score 内容策略。
- 外网补搜作为“证据不足，补充搜索”按钮，不单独成为页面。
- 保留现有认知健康度与画像，但并入上述结构，不再作为孤立卡片。

### D. 行动

采用一条可视化状态管道：

**问题池 → 知识缺口 → 内容计划 → 内容制作 → 已发布 → 复测结果**

- 问题池：列表、平台明细、种子词生成、监测结果生成。
- 缺口：检测、知识缺口/证据缺口分类、生成计划。
- 计划：规则生成、LLM 规划、手动新建、48 子项压力算法、市场信号转计划。
- 制作：内容生成、启发式评分、模型质检、FAQ 与知识增强 FAQ。
- 发布：登记发布 URL 和时间，不伪装成平台自动发布。
- 复测：发布前后推荐率、引用率、覆盖问题和内容效果对比。
- 自动闭环放在“批量自动生产”高级操作中，并明确消耗模型额度。

### E. 资料

拆成“企业事实”和“内容资产”两个页签。

- 企业事实：8 大类左树、总覆盖率、子项详情、已有资料、覆盖问题、来源证据、一键生成补充计划、刷新重算、Word 导出。
- 知识库同步：扫描候选、第一次初始化、增量同步，明确 GEO 只读知识库。
- 内容资产：搜索、上传、CRUD、详情、引用效果、发布信息、媒体附件。
- 企业画像作为企业事实页的摘要视图。
- 向量化由保存/上传后的后台状态表达，不给普通用户一个“向量化”按钮。

### F. 市场

拆成“关注对象 / 市场信号 / 链接收录”三个页签。

- 关注对象：新增、删除竞品或关键词，触发采集。
- 市场信号：查看信号，提取可核验事实，确认、忽略、转内容计划。
- 链接收录：链接 CRUD、单条检测、批量检测、收录趋势。
- URL 爬取放在新增链接后的辅助动作中。
- 关键词拓展放在新增关注对象和问题生成器中，不单独设页面。

## 3. 仅管理员或高级用户可见

- 已登记模型列表与连通性检测：放在页面右上角“数据与引擎”抽屉。
- 官网诊断：放在“资料 > 企业事实”的高级工具区，异步运行并展示诊断报告。
- 分析引擎统计：只显示健康状态和待处理数量，不暴露内部表名。
- 手动运行周期报告、自动闭环、外网补搜：显示额度提示、预计耗时和运行状态。
- 原始回答与分析结果：普通用户从业务页面钻取；高级用户可切换“查看原始数据”。

## 4. 不给用户看的能力

- `/intelligence/recover`：内部恢复动作，自动重试或运维触发。
- `/intelligence/analyze`：内部分析入队，由监测和补搜流程自动触发。
- `/monitor/pool`：旧问题池，使用 `/distill/questions` 替代。
- `/monitor/batch`、`/monitor/check`：执行实现细节，由统一运行按钮封装。
- `/knowledge/materials/vectorize`：素材处理实现细节，后台自动执行并显示索引状态。
- `/knowledge/media/{filename}`：资源读取接口，不是功能入口。
- `/health`、`/intelligence/stats`：运维状态，只转译成健康提示。
- `/geo/consumer/*`、`/eios/export/knowledge-index`：顾问交接面且尚未放行，不进入 GEO UI。
- `/knowledge/reset`：不进入业务界面；如未来保留，只能在管理员设置中二次确认并输入企业名。

## 5. 页面组合原则

1. **一个结论只出现一次**：总览给结论，详情页负责解释，不在多个卡片重复同一指标。
2. **从数字直接到动作**：缺口数字可点击并直接创建计划；信号可直接转计划；错误认知可直接定位证据。
3. **默认展示业务语言**：把 evidence、factor、harvest、distill 翻译成证据、认知因子、补充搜索、内容闭环。
4. **运行与保存要区分**：调用模型的按钮标明“AI 运行”、耗时与额度；本地计算标明“重新计算”；保存操作即时反馈。
5. **空状态也是流程导航**：没有数据时告诉用户先完成哪一步，并提供唯一主按钮。
6. **详情用抽屉，主线不跳走**：回答原文、证据链、素材详情、子项详情统一使用右侧抽屉。
7. **批量能力收进工具栏**：选择记录后才出现批量运行、删除、复测，避免常驻按钮噪音。

## 6. 补齐顺序

### 第一阶段：形成可用闭环

1. 资料体检完整页：子项详情、一键补计划、刷新、Word 导出。
2. 洞察完整页：汇报层、差距矩阵、因子对比、证据抽屉。
3. 内容闭环：发布登记、复测、效果回写、内容质检。
4. 市场完整页：关注列表、信号操作、链接 CRUD。

### 第二阶段：补齐专业分析

1. 监测六类分析页共用版式。
2. 监测对象和任务趋势、任务聚合详情、Markdown 导出。
3. FAQ、内容机会、手动计划、客户问题生成。
4. 最新报告展示、生成状态和管理摘要。

### 第三阶段：高级工具与治理

1. 官网诊断和报告。
2. 引擎状态与连通性检测。
3. 外网补搜与自动闭环。
4. 媒体附件、企业画像与素材索引状态。

## 7. 验收标准

- 所有应给用户看的能力都有入口，但一级导航不超过 6 项。
- 任一指标最多两次点击可到原始证据。
- 任一缺口最多两次点击可进入内容计划。
- 所有模型调用都有耗时/额度提示、运行态、失败态和重试。
- 所有删除、忽略、发布、批量运行操作都有明确反馈。
- Client 内嵌态无双重导航、无横向溢出、主要页面不出现大面积无意义留白。
- 内部接口、破坏性操作和未放行接口不会暴露给普通用户。
